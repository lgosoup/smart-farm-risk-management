# Smart Farm Risk Management System

물로 키우는 스마트팜(수경재배)의 상태를 자동으로 살피고, 위험하면 알려 주고, 냉각기·펌프 같은 장치를 알맞게 돌려 주는 프로그램입니다. 작물을 안전하게 지키면서 전기를 덜 쓰고 탄소 배출도 줄이는 것을 목표로 합니다.

## 작품 개요

### 어떤 문제를 푸나요?

수경재배에서는 물의 온도(수온), 산도(pH), 양분 농도(EC), 물이 흐르는 양(유량), 물의 탁한 정도(탁도)를 계속 맞춰 줘야 합니다. 그런데 실제 농장에서는 세 가지가 어렵습니다.

1. **값 하나만 보고 판단하기 어렵습니다.** 수온이 조금 높고 유량도 조금 낮으면, 하나씩은 괜찮아 보여도 둘이 겹치면 위험할 수 있습니다.
2. **장치를 너무 많이 돌립니다.** 흔히 쓰는 "몇 도 넘으면 냉각기 켜기" 방식은 단순하지만, 필요 이상으로 오래 돌아 전기를 많이 씁니다.
3. **농장마다 사정이 다릅니다.** 같은 냉각기라도 온실의 단열 상태나 기계의 노후 정도에 따라 효과가 다릅니다. 장치를 바꾸거나 추가하면 설정을 다시 손봐야 합니다.

### 어떻게 푸나요?

- **사람처럼 종합해서 판단합니다.** "수온이 약간 높다", "유량이 조금 부족하다" 같은 애매한 표현을 그대로 다루는 퍼지 로직으로 여러 값을 함께 보고, 위험도를 0~100점과 `안정 / 경계 / 주의 / 경고 / 위험 / 긴급` 단계로 알려 줍니다.
- **미리 계산해 보고 장치를 고릅니다.** 장치를 어떻게 돌릴지 여러 경우를 만들어, 각각 돌렸을 때 한 시간 뒤 물 상태가 어떻게 될지 예측합니다. 그중 작물을 적정 범위 안에 두면서 전기를 가장 적게 쓰는 방법을 고릅니다.
- **농장에 맞춰 스스로 배웁니다.** 장치를 돌린 뒤 실제로 물 상태가 얼마나 바뀌었는지 기록해서, "이 온실의 이 냉각기는 생각보다 약하다" 같은 사실을 스스로 알아냅니다.
- **깨끗하고 싼 전기를 쓰는 시간에 미리 일합니다.** 시간대마다 전기의 탄소 배출량과 요금이 다릅니다. 곧 덥고 비싼 시간이 온다고 예상되면, 그 전에 물을 조금 더 식혀 둡니다(저수조 예냉).
- **작물이 바뀌어도 기준을 새로 잡습니다.** 농촌진흥청 농사로 자료와 논문에서 작물별 적정 수온·pH·EC를 찾아 기준을 만듭니다. 바질, 상추, 딸기, 토마토, 와사비 기준이 들어 있습니다.

```
센서 값 ─▶ 위험도 판단 ─▶ 알림·기록
              │
              ├─▶ 장치 운전 계획 (예측 → 비교 → 선택) ─▶ 장치 명령
              ├─▶ (요청하면) AI가 쉬운 말로 설명
              └─▶ (매일 새벽) 판단 기준을 조금씩 개선 ◀─ 카메라로 본 잎 상태
```

## 주요 기능

### 1. 위험도 판단 (`fuzzyLozic/`)
- 수온, pH, EC, 유량, 탁도를 함께 보고 위험도를 계산합니다. 기온과 습도는 참고용으로 기록만 합니다.
- "수온이 높고 유량이 낮으면 위험" 같은 규칙 28개로 판단하고, 어떤 규칙 때문에 그 결론이 나왔는지 함께 남깁니다.
- 값이 갑자기 튀거나, 계속 나빠지거나, 좀처럼 회복되지 않는 흐름도 잡아냅니다.
- `위험`이 세 번 연속 나오면 `긴급`으로 올립니다.
- 센서 고장처럼 보이는 값은 따로 표시해 둡니다.

### 2. 장치 운전 계획 (`netzero/`, `fuzzyLozic/control/`)
- 냉각기, 순환펌프, 산소펌프, 환풍기, 양액 공급 펌프, 급수 밸브를 얼마나 돌릴지 여러 조합을 만들어 비교합니다.
- **작물 안전이 먼저입니다.** 적정 범위를 지키는 조합만 남기고, 그 안에서 전기·탄소·양액·물 사용과 장치를 자주 껐다 켜는 것을 줄이는 조합을 고릅니다.
- 한 시간 뒤만 보지 않고 세 시간 앞까지 내다보고 고릅니다.
- 양분이 너무 진해지면 급수 밸브로 물을 보충해 묽힙니다.
- 고른 계획은 실제 장치 명령(아두이노 핀 신호)으로 바뀝니다. 냉각기는 펌프와 팬을 먼저 켜고 나중에 끄는 보호 순서를 따릅니다.

### 3. 장치 목록만 바꾸면 되는 구조 (`netzero/profiles/facilities/`)
- 장치를 이름이 아니라 "수온을 내린다", "유량을 올린다" 같은 **역할**과 소비 전력, 대략적인 효과로 적어 둡니다.
- 장치를 추가하거나 빼도 이 목록 파일만 고치면 됩니다. 프로그램 코드는 바꾸지 않습니다.
- 예시로 아두이노로 만든 소형 재배대, 칠러 2대짜리 중형 온실, 단열이 약한 온실 세 가지가 들어 있습니다.

### 4. 스스로 배우는 예측
- 장치를 돌린 결과를 볼 때마다 온실의 열 손실, 장치별 냉각 효과, 양분 변화 속도를 고쳐 나갑니다.
- 처음에는 장치 목록에 적힌 대략적인 값으로 시작하고, 하루 정도 지나면 수온 예측 오차가 절반 가까이 줄어듭니다.
- 장치가 고장 나서 약해지거나 하나가 빠져도 다시 맞춰 갑니다.

### 5. 가상 스마트팜과 비교 실험 (`netzero/simulator.py`, `netzero/experiment.py`)
- 실제 농장 대신 컴퓨터 안에 가상 농장을 만들어 실험합니다. 가상 농장의 진짜 특성은 제어 프로그램에게 숨겨서, 실제처럼 운전하면서 배우게 합니다.
- 세 가지 운전 방식을 같은 날씨, 같은 농장에서 비교합니다.
  - **A** 정해진 온도를 넘으면 켜는 흔한 방식
  - **C** 매시간 계산하고 스스로 배우는 방식
  - **D** C에 시간대별 탄소·요금과 저수조 예냉을 더한 방식
- 폭염, 냉각기 고장, 장치 제거, 작물 변경 같은 상황도 실험할 수 있습니다.
- `netzero_app.py` 화면에서 버튼을 눌러 결과를 그래프로 볼 수 있습니다.

### 6. 판단 기준 스스로 개선 (`fuzzyLozic/improvement/`)
- 매일 한 번, 판단 기준을 아주 조금 바꿔 보는 후보 중 하나를 고릅니다.
- 카메라로 찍은 잎 색이 좋아졌는지, 경고가 줄었는지를 보고 어떤 변경이 좋았는지 점수를 매깁니다.
- 바꿀 수 있는 폭에 한도를 두어 기준이 한 번에 크게 흔들리지 않게 합니다.

### 7. 잎 건강 분석 (`smartfarm/vision/`)
- 사진에서 초록색이 얼마나 진하고 선명한지 계산해 잎의 건강 점수를 냅니다.
- 어제 사진과 비교해 나아졌는지 나빠졌는지도 함께 봅니다.

### 8. AI 설명 (`llm/`)
- 판단 결과와 그 근거를 컴퓨터 안에서 도는 작은 AI(Qwen3-4B)가 사람이 읽기 쉬운 말로 풀어 줍니다.
- AI는 설명만 합니다. 위험 단계는 바꾸지 않습니다.
- 그래픽카드나 AI 패키지가 없으면 간단한 요약으로 대신합니다.

### 9. 작물 기준 만들기 (`smartfarm/`, `research/`)
- 농사로 자료와 논문을 읽어 "적정 수온은 20~25℃" 같은 문장에서 숫자를 뽑아냅니다.
- 뽑은 값을 검증해 작물 기준 파일로 만들고, 위험도 판단과 장치 운전 목표에 반영합니다.

### 10. 자동 운전과 확인 화면
- `orchestrator.py`: 한 시간마다 센서 값 읽기 → 위험도 판단 → 기록 → 장치 운전 계획 → AI 설명 요청 처리를 반복합니다. 매일 새벽 3시 이후에는 판단 기준 개선을 한 번 실행합니다.
- `streamlit_app.py`: 센서 값을 바꿔 보면서 위험도가 어떻게 바뀌는지 바로 확인하는 화면입니다.

## 실험 결과

바질, 여름 남부 날씨, 7일 동안 가상 농장에서 돌린 결과입니다. 절감률은 흔한 방식(A)과 비교한 값입니다.

| 상황 | 방식 | 적정 범위 유지율 | 전기 사용(kWh) | 전기 절감 | 탄소 감축 | 요금 절감 |
|---|---|---|---|---|---|---|
| 아두이노 소형 재배대 | A | 100% | 8.6 | - | - | - |
| | C | 100% | 6.7 | 21.6% | 23.0% | 19.2% |
| | D | 100% | 6.8 | 20.9% | 22.3% | 18.6% |
| 중형 온실 (칠러 2대) | A | 100% | 53.0 | - | - | - |
| | C | 100% | 31.5 | 40.5% | 41.5% | 41.3% |
| | D | 100% | 30.6 | 42.2% | 42.9% | 43.3% |
| 단열이 약한 온실 | A | 64.9% | 51.6 | - | - | - |
| | C | 61.9% | 42.4 | 17.8% | 17.7% | 19.2% |
| | D | 62.5% | 42.5 | 17.7% | 17.6% | 19.4% |
| 중형 온실 + 폭염 + 3일째 칠러 A 성능 절반으로 저하 | A | 100% | 77.6 | - | - | - |
| | C | 81.5% | 52.8 | 31.9% | 33.2% | 31.7% |
| | D | 81.5% | 52.5 | 32.3% | 33.3% | 32.8% |
| 소형 재배대 + 딸기 + 2일째 환풍기 제거 | A | 100% | 12.6 | - | - | - |
| | C | 100% | 10.3 | 18.4% | 19.6% | 16.2% |
| | D | 100% | 10.4 | 17.7% | 19.0% | 16.0% |

- **적정 범위 유지율**은 수온·EC·유량·탁도가 모두 작물에게 알맞은 범위 안에 있던 시간의 비율입니다.
- 칠러 2대짜리 온실에서 절감이 가장 컸습니다. C와 D가 운전하면서 구형 칠러의 효율이 낮다는 걸 알아내고 신형을 주로 썼기 때문입니다.
- 처음 하루 동안 수온 예측 오차는 약 0.15℃였고, 그 뒤로는 약 0.08℃로 줄었습니다.
- **저수조 예냉(D)의 효과는 시설에 따라 다릅니다.** 중형 온실에서는 C보다 탄소와 요금을 2%p쯤 더 줄였습니다. 소형 재배대에서는 오히려 조금 늘었습니다. 지금 쓰는 시간대별 탄소·요금 값은 단순화한 가정값이라 시간대 간 차이가 작습니다. 실제 시간대별 값이나 태양광 발전이 있는 농장이라면 차이가 더 커질 수 있습니다.
- **아직 약한 상황이 두 가지 있습니다.**
  - 단열이 약한 온실에서는 적정 범위 유지율이 A보다 2~3%p 낮습니다.
  - 폭염 중 칠러가 갑자기 고장 나면 유지율이 81.5%까지 떨어집니다. 고장을 알아채는 속도를 높이는 것이 다음 과제입니다.
- 양분이 너무 진한 상태(EC 2.3)에서 시작해도, 급수 밸브로 물을 보충해 12시간 안에 적정 범위로 돌아옵니다.

## 사용 기술

| 구분 | 내용 |
|---|---|
| 언어 | Python 3.10 이상 |
| 위험도 판단 | 퍼지 로직 (Mamdani 추론, 무게중심법). 외부 라이브러리 없이 직접 구현 |
| 장치 운전 계획 | 경우의 수를 모두 비교하는 다목적 최적화. 작물 안전을 먼저 보고 에너지를 나중에 봄 |
| 스스로 배우는 예측 | 재귀 최소제곱법(RLS). 새 기록이 들어올 때마다 예측식을 조금씩 고침 |
| 기준 개선 | UCB1 밴딧 알고리즘. 여러 후보를 번갈아 시험하며 좋은 것을 찾음 |
| 가상 실험 | 시설·날씨·전력망 정보를 파일로 바꿔 끼우는 시뮬레이터 |
| AI 설명 | Qwen3-4B, Hugging Face Transformers, 4bit 경량화(bitsandbytes), PyTorch |
| 사진 분석 | OpenCV, NumPy (초록색 지수 ExG, 채도) |
| 자료 수집 | 농촌진흥청 농사로 API, Semantic Scholar 논문 API |
| 문서 분석 | 농업 문서에서 숫자와 단위를 뽑는 규칙 기반 처리 |
| 화면 | Streamlit, Matplotlib |
| 하드웨어 | Arduino (펌프 드라이버 BTS7960, 펠티어 냉각기, 팬, LED) |
| 테스트 | pytest |


## 설치와 실행

### 설치
```bash
# Windows: 가상환경을 만들고 필요한 패키지를 설치합니다
setup.bat
# 또는 PowerShell
.\setup.ps1

# 직접 설치
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# AI 설명까지 쓰려면 (NVIDIA 그래픽카드 필요)
setup.bat gpu
# 또는
pip install -r requirements-gpu.txt --extra-index-url https://download.pytorch.org/whl/cu118
```

### 실행
```bash
# 위험도 확인 화면
streamlit run streamlit_app.py

# 운전 방식 비교 실험 화면
streamlit run netzero_app.py

# 자동 운전 (한 시간 간격, Ctrl+C로 종료)
python orchestrator.py
```

### 비교 실험
```bash
# 시설 3종 × 운전 방식 A, C, D, 7일
python -m netzero.experiment --days 7 --controllers A C D

# 폭염 중 3일째에 칠러 A 성능이 절반으로 떨어지는 상황
python -m netzero.experiment --facility mid_greenhouse --climate heatwave --event degrade:chiller_a:0.5@3

# 딸기로 작물을 바꾸고 2일째에 환풍기를 떼어 내는 상황
python -m netzero.experiment --facility small_rack --crop strawberry --event remove:vent_fan@2
```

결과는 `netzero/results/`에 저장됩니다. 새 시설을 실험하려면 `netzero/profiles/facilities/`에 장치 목록 파일을 하나 추가하면 됩니다. 파일 안의 `simulator_truth`는 가상 농장만 읽는 숨은 실제 특성입니다.

### 작물 바꾸기
```bash
# 들어 있는 작물 기준으로 바로 바꾸기
python -m smartfarm.activate_crop basil

# 작물 목록과 현재 작물 보기
python -m smartfarm.generate_crop_profile --list
python -m smartfarm.generate_crop_profile --status

# 새 작물 기준 만들기 (농사로 API 키 필요)
python -m smartfarm.generate_crop_profile --crop 바질 --activate
```

| 환경 변수 | 용도 |
|---|---|
| `NONGSARO_API_KEY` | 농사로 API 키 (공공데이터포털에서 발급) |
| `SEMANTIC_SCHOLAR_API_KEY` | 논문 검색 API 키 (없어도 됨) |

## 데이터 파일

| 파일 | 내용 |
|---|---|
| `data/inputs.json` | 현재 센서 값 (수온, pH, EC, 유량, 탁도, 기온, 습도) |
| `data/crop_config.json` | 지금 키우는 작물과 그 기준 |

실행하면 `data/`에 위험도 결과(`outputs.json`), 장치 운전 결과(`device_control_outputs.json`), 기준 개선 상태(`improvement_state.json`), 각종 기록(`history_*.jsonl`, `alerts.jsonl`)이 생깁니다. 이 파일들은 실행할 때마다 바뀌므로 git에 올리지 않습니다.
